# Receipts v0.3 handoff

v0.2 was merged before this work. The v0.3 source implements all five approved items: atomic fenced claim lifecycle, named policy/rate denials, local Ed25519 signed receipts and offline badges, scored conformance evaluation receipts, and optional OpenTelemetry wrappers.

Start with README.md and `npm ci && npm test`. New admission outcomes are separate from the four destination verdicts. TTL only frees unused reservations; a dispatched uncertain action never becomes retryable. The SDK keeps DuplicateWriteError compatibility and adds persisted admission details plus PolicyDeniedError. Core remains dependency-free.

The real GitHub example remains explicitly gated with --live and uses synthetic issues. Audits and signed proof previews stay under ignored .receipts/. The public docs/evaluations/github-0.3.0.json is a self-attested fixed-fixture benchmark, with explicit counts and denominators. It includes no audit, payloads, credentials or machine paths.

Before npm release follow docs/RELEASE.md. No npm publication, version tag, registry or marketplace submission is established by this source work. The original OS was not modified.

## Improvement pass after the v0.3 review (2026-09-25)

Branch `claude/relaxed-brown-lnlx6q` builds on `codex/v0.3-gap-closure`. It closes the review's P0 (MCP exposure of admission, policy, digests, and signed proofs), the P1 judgment calls, the P2 polish, and the three enterprise P0 items (`receipts bug-report`, `receipts doctor --json`, the error taxonomy). Everything is source work: no version bump, no npm publication, no registry or marketplace submission.

What changed, by area:

- Core admission. `claim(action, policy)` refuses a forbidden write before any reservation exists as one audited registry-less `policy_denied` record; identity refusals keep precedence and `dispatch` remains the enforcement boundary. `registry.evaluate(action, policy)` is a pure pre-check. `validatePolicy` is exported. An approval is spent by any other action on its account that may have written or holds a live reservation; released or expired unused reservations free it (previously any past claim spent it forever).
- MCP server. Fourteen tools: the six evidence tools plus `receipts.digest`, `receipts.policy`, `receipts.claim`, `receipts.dispatch`, `receipts.release`, `receipts.complete`, `receipts.sign`, `receipts.badge`. Host configuration through `--policy`, `--claim-ttl`, `--signing-key` and matching environment variables. Observe and recheck complete a dispatched lease when a matching independent read binds. Error envelopes carry `hint` and `docs` from the taxonomy; observing a destination for a live undispatched claim returns `warnings: ["claim_not_dispatched"]`.
- Support CLI. `receipts doctor` is human-readable by default; `receipts doctor --json` emits `{ ok, version, checks: [{ name, ok, detail }] }`. `receipts bug-report` assembles a redacted support bundle as a prefilled GitHub issue (never submitted). The `receipts` binary now points at `dist/receipts.js`.
- Error taxonomy. `packages/core/src/errors.ts` documents every code with cause, fix, and docs link; `docs/ERRORS.md` is generated by `npm run docs:errors`; a core test rejects any code that appears in source without an entry, any orphaned entry, and a stale docs page. Proof refusals became coded `ReceiptsError`s; REST envelopes carry hint and docs.
- OpenTelemetry. `receipts.receipt.issue` fires for every issued receipt document with the verdict attribute, not only completions.
- Repository hygiene. `npm test` no longer rewrites `docs/evaluations/github-0.3.0.json`; `npm run evaluate:github` regenerates it deliberately. CI runs `npm run pack:check`. Every publishable package declares npm keywords.

Public API shape changes to note before release (nothing is published yet):

- `IdempotencyRegistry.claim` gains an overload. Calls without a policy keep the exact `ClaimDecision` type; calls with a policy return `ClaimDecision | PolicyDeniedDecision`. Exhaustive switches over the two-variant type are unaffected unless they pass a policy.
- `AuditEntry` may now contain a `policy_denied` event without `registry` metadata (verdict `prewrite`). Old chains validate unchanged; consumers that assumed every `policy_denied` carries a lease must handle the pre-claim form.
- `DoctorCheck.check` was renamed to `DoctorCheck.name`; `DoctorReport` gains `version`. The default `receipts doctor` output is no longer JSON; use `--json`. The `receipts` bin moved from `dist/doctor.js` to `dist/receipts.js` (`doctor.ts` keeps exporting `doctor()`).
- Proof functions that threw plain `Error` now throw `ReceiptsError` with codes (`invalid_signing_key`, `invalid_public_key`, `invalid_receipt`, `receipt_audit_mismatch`, `badge_requires_independent_completion`, `invalid_receipt_url`). Messages are unchanged and `ReceiptsError extends Error`. `verifySignedReceipt` still returns the generic `invalid_proof`.
- SDK argument and payload `TypeError`s carry a `code` property (`invalid_write`, `invalid_payload`). Their class is unchanged.
- MCP `receipts.observe`/`receipts.recheck` results may include `admission` and `warnings`; error envelopes include `hint` and `docs`. REST error envelopes include `hint` and `docs`.
- OTel: the issue span's meaning changed from "a completion was issued" to "a receipt was issued". Dashboards counting the span as completions must filter `receipts.verdict = complete`.

Judgment calls from the review, with the decision taken: policy is evaluated at claim for early feedback and at dispatch for enforcement (implemented, both audited). The strict approval-reuse rule was narrowed to live reservations and possible writes because an abandoned reservation never reached the destination, while two live reservations under one approval could both dispatch. The OTel issue span was made to match its name rather than renamed. The enterprise handoff referenced `receipts-enterprise-handoff.md`, which is not in the repository; the three items were built from the handoff text alone.
